1IPD Dashboard คืออะไร

เว็บแอปที่ดึงข้อมูลผู้ป่วยในจากฐานข้อมูล HOSxP แบบสด แล้วแสดงเป็นอินโฟกราฟิกหน้าเดียว 12 บล็อก ผู้บริหารและหัวหน้าหอผู้ป่วยเปิดดูได้ทั้งบนคอมพิวเตอร์และมือถือ และกดส่งออกเป็นไฟล์ JPG / PNG / PDF ไปใช้ในการประชุมหรือส่งเข้ากลุ่มไลน์ได้ทันที

  • อ่านอย่างเดียว — ไม่เขียน ไม่แก้ข้อมูลใน HOSxP
  • ไม่มีข้อมูลรายบุคคล — แสดงเฉพาะตัวเลขรวม ไม่มี HN / AN / ชื่อผู้ป่วย
  • ไม่ต้องคีย์ข้อมูลเพิ่ม — ใช้ข้อมูลที่ HOSxP บันทึกอยู่แล้ว
  • ทำงานในโรงพยาบาล — ไม่ส่งข้อมูลไปเซิร์ฟเวอร์ภายนอก ไม่เรียกฟอนต์/สคริปต์จากอินเทอร์เน็ต
  • ใช้ฟรี — โอเพนซอร์ส ใบอนุญาต MIT แก้ไขต่อได้

ไฟล์ชุดติดตั้ง — ดาวน์โหลด ipd_dashboard-{{VERSION}}.zip จาก github.com/nopneo/ipd-dashboard-wnk/releases ภายในมีโปรแกรม คู่มือนี้ INSTALL.md SECURITY.md และ .env.example (ตัวอย่างค่าตั้ง) — ไม่มีรหัสผ่านหรือข้อมูลของโรงพยาบาลใดติดมา

3สร้างบัญชีฐานข้อมูลอ่านอย่างเดียว

ล็อกอินฐานข้อมูล HOSxP ด้วยบัญชีผู้ดูแล (เช่น ผ่าน HeidiSQL หรือคำสั่ง mysql) แล้วรัน โดยเปลี่ยน 10.0.0.20 เป็น IP ของเครื่องที่จะติดตั้งแดชบอร์ด และตั้งรหัสผ่านให้ยาวและเดายาก

CREATE USER 'ipd_ro'@'10.0.0.20' IDENTIFIED BY '<รหัสผ่านยาวอย่างน้อย 16 ตัว>';
GRANT SELECT ON hos.* TO 'ipd_ro'@'10.0.0.20';
FLUSH PRIVILEGES;
  • ระบุ IP ของเครื่องแดชบอร์ดแทน '%' — บัญชีนี้จะล็อกอินได้จากเครื่องนั้นเครื่องเดียว
  • ใช้ฐานข้อมูลชื่ออื่นที่ไม่ใช่ hos ให้แก้ทั้งในคำสั่งนี้และค่า DB_NAME
  • แม้บัญชีมีสิทธิ์เขียน แดชบอร์ดยังตั้ง session เป็น READ ONLY ให้อีกชั้น แต่ไม่ควรพึ่งชั้นนี้อย่างเดียว

ทดสอบจากเครื่องแดชบอร์ด:

mysql -h <IP ฐานข้อมูล> -u ipd_ro -p hos -e "select count(*) from ipt where dchdate is null"

ได้ตัวเลขผู้ป่วยในปัจจุบันออกมา = พร้อมติดตั้ง

4ติดตั้งบน Linux (แนะนำ)

ตัวอย่างใช้ AlmaLinux 9 ติดตั้งที่ /opt/ipd_dashboard และรันด้วยผู้ใช้ ipd (ไม่ใช้ root) ทุกคำสั่งรันด้วย root หรือ sudo

  1. สร้างผู้ใช้สำหรับรันโปรแกรม (ล็อกอินเข้าเครื่องไม่ได้) 
    useradd -r -M -d /var/lib/ipd -s /sbin/nologin ipd
  2. แตกไฟล์และติดตั้งไลบรารี 
    dnf install -y python3 unzip                 # Ubuntu: apt install -y python3-venv unzip
unzip ipd_dashboard-{{VERSION}}.zip -d /opt
cd /opt/ipd_dashboard
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
  3. ตั้งค่าฐานข้อมูล — คัดลอกไฟล์ตัวอย่างแล้วแก้ DB_HOST DB_USER DB_PASS 
    cp .env.example .env
nano .env
chown -R root:root /opt/ipd_dashboard        # โค้ดเป็นของ root → โปรแกรมแก้โค้ดตัวเองไม่ได้
chown root:ipd .env && chmod 640 .env       # รหัสผ่าน: root แก้ได้ ipd อ่านได้ คนอื่นมองไม่เห็น
  4. ทดลองรัน แล้วเปิด http://<IP เครื่อง>:5700/ จากเครื่องอื่นในโรงพยาบาล (กด Ctrl+C เพื่อหยุด) 
    runuser -u ipd -- .venv/bin/python app.py
  5. ติดตั้งเบราว์เซอร์สำหรับปุ่มส่งออก (ข้ามได้ถ้าไม่ใช้ — แล้วตั้ง IPD_EXPORT=0) 
    dnf install -y epel-release && dnf install -y chromium-headless
# Ubuntu: ติดตั้ง google-chrome-stable จาก dl.google.com (chromium ของ Ubuntu เป็น snap ใช้กับ service ไม่สะดวก)
  6. ตั้งเป็นบริการ ให้เปิดเองทุกครั้งที่เครื่องรีสตาร์ต — สร้างไฟล์ /etc/systemd/system/ipd-dashboard.service 
    [Unit]
Description=IPD Dashboard
After=network.target

[Service]
User=ipd
Group=ipd
WorkingDirectory=/opt/ipd_dashboard
ExecStart=/opt/ipd_dashboard/.venv/bin/gunicorn -w 3 -t 120 -b 0.0.0.0:5700 app:app
Restart=always
Environment=HOME=/var/lib/ipd
StateDirectory=ipd
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
CapabilityBoundingSet=

[Install]
WantedBy=multi-user.target
    systemctl daemon-reload
systemctl enable --now ipd-dashboard
systemctl status ipd-dashboard               # ต้องขึ้น active (running)
  7. เปิด firewall เฉพาะวงในของโรงพยาบาล (ถ้าจะเปิดผ่านโดเมน ดูหัวข้อ 9 แทน) 
    firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=10.0.0.0/8 port port=5700 protocol=tcp accept'
firewall-cmd --reload
ทำไมไม่ใช้ root — ถ้าโปรแกรมถูกเจาะ ผู้บุกรุกได้แค่สิทธิ์ของผู้ใช้ ipd ซึ่งแก้โค้ด อ่านไฟล์ระบบ หรือยกระดับสิทธิ์ไม่ได้ และปุ่มส่งออกจะเปิด sandbox ของ Chromium ได้ (root ต้องปิด)

5ติดตั้งบน Windows

  1. ติดตั้ง Python 3.11 ขึ้นไปจาก python.org (ติ๊ก Add python.exe to PATH) และมี Google Chrome หรือ Microsoft Edge
  2. แตก zip ไว้ที่ C:\ipd_dashboard แล้วเปิด PowerShell ในโฟลเดอร์นั้น 
    python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
notepad .env
  3. ทดลองรัน แล้วเปิด http://localhost:5700/ 
    .venv\Scripts\waitress-serve --listen=0.0.0.0:5700 app:app
  4. ตั้งให้เปิดเองตอนเครื่องเปิด: ใช้ Task Scheduler (At startup, รันคำสั่งข้อ 3 ในโฟลเดอร์นี้) หรือ NSSM สร้างเป็น Windows Service · ตั้งสิทธิ์ไฟล์ .env ให้อ่านได้เฉพาะบัญชีที่รันโปรแกรมและผู้ดูแล
  5. เปิด Windows Firewall ขาเข้า TCP 5700 เฉพาะเครือข่ายของโรงพยาบาล

6ติดตั้งด้วย Docker

มี Dockerfile 2 แบบ ทั้งคู่ใช้ Alpine Linux และรันด้วยผู้ใช้ธรรมดา (uid 10001)

docker build -t ipd-dashboard .                          # ไม่มีปุ่มส่งออก (image เล็ก ช่องโหว่น้อย)
docker build --target export -t ipd-dashboard-export .   # มี Chromium สำหรับปุ่มส่งออก
docker run -d --name ipd -p 5700:8080 --env-file .env --restart unless-stopped ipd-dashboard
  • รหัสฐานข้อมูลส่งผ่าน --env-file ตอนรันเท่านั้น ไม่ฝังลงใน image
  • โลโก้ของโรงพยาบาลใส่ด้วย -v /path/hospital_logo.png:/app/static/img/hospital_logo.png:ro

9เปิดผ่านโดเมนของโรงพยาบาล (reverse proxy)

ถ้ามีเว็บเซิร์ฟเวอร์ของโรงพยาบาลอยู่แล้ว วางแดชบอร์ดไว้ใต้ path เช่น https://<โดเมน>/ipd/ โดยไม่ต้องเปิดพอร์ต 5700 ออกนอก โปรแกรมอ่าน header X-Forwarded-Prefix แล้วสร้างลิงก์ให้ถูกเอง

Apache

RewriteEngine On
RewriteRule ^/ipd$ /ipd/ [R=302,L]
ProxyPass        /ipd/ http://127.0.0.1:5700/ timeout=120
ProxyPassReverse /ipd/ http://127.0.0.1:5700/
<Location /ipd/>
  RequestHeader set X-Forwarded-Prefix /ipd
  RequestHeader set X-Forwarded-Proto https
</Location>
ก่อนแก้ค่า Apache — สำรองไฟล์ก่อน → ตรวจด้วย httpd -t (Ubuntu: apache2ctl -t) → ผ่านแล้วค่อย systemctl reload httpd · ถ้ามีบรรทัด ProxyPass / ส่งทั้งเว็บไปที่อื่น ต้องวางบล็อกนี้ ก่อน บรรทัดนั้น ไม่งั้น /ipd/ จะถูกส่งไปผิดที่

Nginx

location = /ipd { return 302 /ipd/; }
location /ipd/ {
    proxy_pass http://127.0.0.1:5700/;
    proxy_set_header Host               $host;
    proxy_set_header X-Forwarded-Prefix /ipd;
    proxy_set_header X-Forwarded-Proto  $scheme;
    proxy_read_timeout 120s;
}

ตรวจด้วย nginx -t แล้ว systemctl reload nginx · เมื่อใช้ proxy แล้ว ตั้ง firewall ให้พอร์ต 5700 รับเฉพาะเครื่อง proxy (หรือให้ gunicorn ฟัง -b 127.0.0.1:5700)

ถ้าเปิดออกอินเทอร์เน็ต — โปรแกรมไม่มีระบบล็อกอิน ใครมีลิงก์ก็เห็นตัวเลขรวมของโรงพยาบาลได้ ควรจำกัดด้วย VPN / Cloudflare Access / Basic Auth และตั้ง rate limit ที่ proxy (รายละเอียดหัวข้อ 11)

  • http://<เครื่อง>:5700/healthz ตอบ {"status":"ok"}
  • หน้าแรกขึ้นชื่อและโลโก้ของโรงพยาบาลถูกต้อง
  • ผู้ป่วยในปัจจุบัน ตรงกับจำนวนใน HOSxP (หน้าทะเบียนผู้ป่วยใน ที่ยังไม่จำหน่าย)
  • ตาราง ครองเตียงรายตึก มีครบทุกตึก — ไม่ครบ = ตรวจ ward.ward_active='Y' และ ward.bedcount ใน HOSxP
  • เตียงทั้งหมด ตรงกรอบของโรงพยาบาล — ไม่ตรง = ตั้ง IPD_TOTAL_BEDS
  • เลือกช่วงวันที่ย้อนหลัง 1 เดือน ยอดรับใหม่/จำหน่ายใกล้เคียงรายงานประจำเดือนที่ใช้อยู่
  • กดปุ่ม ⬇ JPG ได้ไฟล์ภายใน ~15 วินาที (ถ้าไม่ใช้ปุ่มส่งออก ตั้ง IPD_EXPORT=0)
  • เปิดจากมือถือในเครือข่ายโรงพยาบาลได้ และหน้าไม่ล้นจอด้านข้าง
  • รีสตาร์ตเครื่องแล้วบริการกลับมาเอง (systemctl is-enabled ipd-dashboard = enabled)

11ความปลอดภัย

ที่โปรแกรมทำให้แล้ว

  • แสดงเฉพาะตัวเลขรวม ไม่มี HN / AN / ชื่อ ทั้งในหน้าเว็บ API และไฟล์ส่งออก
  • ตรวจรูปแบบวันที่และรหัส ward ก่อนนำไปใช้ใน SQL (กัน SQL injection) · จำกัดช่วงวันที่ 366 วัน
  • ต่อฐานข้อมูลแบบ READ ONLY มี timeout ต่อคำสั่ง และแคชผลลดภาระฐานข้อมูล
  • ปุ่มส่งออกทำทีละงาน ถ้ามีงานค้างตอบ "ไม่ว่าง" ทันที (กันเว็บค้างจากการกดรัว) · เบราว์เซอร์เปิดได้เฉพาะหน้าของตัวเอง
  • โหมด debug ปิดเป็นค่าเริ่มต้น · ไม่เรียกทรัพยากรจากอินเทอร์เน็ต · ตรวจไลบรารีด้วย pip-audit ทุกเวอร์ชัน

ที่โรงพยาบาลต้องทำเอง

  • ใช้บัญชีฐานข้อมูล SELECT อย่างเดียว จำกัด IP และต่อ Replica
  • รันด้วยผู้ใช้ธรรมดา ไม่ใช่ root · .env สิทธิ์ 640 (Linux) ห้ามส่งต่อหรืออัปโหลดขึ้นที่ใด
  • firewall ให้พอร์ต 5700 รับเฉพาะ LAN หรือเครื่อง proxy
  • เปิดออกอินเทอร์เน็ต: HTTPS เท่านั้น + จำกัดผู้เข้าถึง + rate limit (เช่น 60 ครั้ง/นาที/IP และ 5 ครั้ง/นาที สำหรับ /ipd/export.*)
  • อัปเดตแพตช์ระบบปฏิบัติการและเวอร์ชันของแดชบอร์ดเป็นระยะ

พบช่องโหว่ กรุณาแจ้งผู้พัฒนาโดยตรง หรือผ่าน GitHub → Security → Report a vulnerability (ไม่เปิดเป็น issue สาธารณะ)

cd /opt

13แก้ปัญหาที่พบบ่อย

ดู log ก่อนเสมอ: journalctl -u ipd-dashboard -n 50

อาการสาเหตุ / วิธีแก้
บริการไม่ขึ้น หรือหน้าเว็บ error 500ต่อฐานข้อมูลไม่ได้ — ตรวจ DB_HOST / รหัสผ่าน / firewall ฝั่งฐานข้อมูล ด้วยคำสั่งทดสอบในหัวข้อ 3 · Access denied = รหัสผิด หรือบัญชีไม่ได้อนุญาต IP เครื่องนี้
Permission denied: '.env'ตั้งสิทธิ์ใหม่: chown root:ipd .env && chmod 640 .env (มักเกิดหลังแก้ไฟล์ด้วยการคัดลอกทับ)
ภาษาไทยเป็นตัวอักษรแปลก ๆฐานข้อมูลไม่ใช่ tis-620 ตามที่ HOSxP ใช้ทั่วไป — แจ้งผู้พัฒนาพร้อมผลของ show variables like 'character_set%'
ปุ่มส่งออกขึ้น "ส่งออกไม่สำเร็จ"ไม่มี Chromium — ติดตั้งตามหัวข้อ 4 ข้อ 5 · ติดตั้งแล้วยังไม่ได้ ลอง IPD_CHROME_NO_SANDBOX=1
ปุ่มส่งออกขึ้น "กำลังส่งออกไฟล์ของผู้ใช้อื่นอยู่"ปกติ — ทำทีละงาน รอประมาณ 15 วินาทีแล้วกดใหม่
อัตราครองเตียงสูง/ต่ำผิดปกติผลรวม ward.bedcount ไม่เท่ากรอบเตียงจริง — ตั้ง IPD_TOTAL_BEDS
ตึกบางตึกไม่ขึ้นในตารางตึกนั้น ward_active ไม่ใช่ Y หรือ bedcount เป็น 0 ใน HOSxP
CMI ต่ำกว่าความจริงเคสส่วนใหญ่ยังไม่ได้ group DRG (ipt.adjrw ว่าง) — การ์ดบอกจำนวนที่ group แล้วกำกับไว้
ลิงก์ผิดเมื่อเปิดผ่าน /ipd/proxy ไม่ได้ส่ง X-Forwarded-Prefix — ตรวจค่าในหัวข้อ 9
หน้าโหลดช้าฐานข้อมูลหลักรับภาระมาก — ชี้ไป Replica, เพิ่ม IPD_CACHE_TTL, ลดช่วงวันที่

14นิยามตัวชี้วัด

ตัวชี้วัดวิธีคิด (ตารางใน HOSxP)
ผู้ป่วยในปัจจุบันแถวใน ipt ที่ dchdate ว่าง (ยังไม่จำหน่าย)
รับใหม่ / จำหน่ายipt.regdate / ipt.dchdate อยู่ในช่วงที่เลือก · เทียบช่วงก่อนหน้าที่ยาวเท่ากัน
อัตราครองเตียง (ปัจจุบัน)ผู้ป่วยในปัจจุบัน ÷ เตียงตามกรอบ × 100 · เตียงตามกรอบ = IPD_TOTAL_BEDS หรือผลรวม ward.bedcount ของตึกที่เปิดใช้
ครองเตียงเฉลี่ยตลอดช่วงวันนอนรวม ÷ (เตียง × จำนวนวันในช่วง) × 100
วันนอนรวมจำนวนวันที่ผู้ป่วยแต่ละรายนอนอยู่ภายในช่วงที่เลือก (นับวันรับ ไม่นับวันจำหน่าย)
วันนอนเฉลี่ย (ALOS)ค่าเฉลี่ย dchdate − regdate ของผู้ที่จำหน่ายในช่วง
Readmission 30 วันผู้จำหน่ายในช่วงที่กลับมา admit ใหม่ (AN อื่น HN เดิม) ภายใน 30 วันหลังจำหน่าย ÷ ผู้จำหน่าย
ส่งต่อ / ไม่สมัครใจอยู่ / หนีipt.dchtype = 04 / 02 / 03 ตามรหัสมาตรฐาน
จำหน่ายหลัง 16:00 น.เฉพาะแพทย์อนุญาตให้กลับ (dchtype 01) และ dchtime เกินเวลาที่ตั้ง
ยังไม่ลงรหัสโรคหลักผู้จำหน่ายที่ไม่มีแถวใน iptdiag ที่ diagtype='1' · เกิน 10% ขึ้นเตือน
CMIค่าเฉลี่ย ipt.adjrw ของเคสที่ group แล้ว (adjrw > 0)
Bed Turnoverจำนวนผู้จำหน่าย ÷ จำนวนเตียง
รอเตียงadmit แล้วแต่ยังไม่มีแถวเตียงที่เปิดอยู่ใน iptadm

ตัวเลขทุกตัวมาจากฐานข้อมูลจริง ไม่มีค่าประมาณ · ถ้าโรงพยาบาลไม่ได้บันทึกช่องใด ตัวชี้วัดนั้นจะเป็น 0
